# 차계부 시트 구조 분석 (읽기 전용)

2026-10-10에 사용자가 지정한 스프레드시트를 읽기 전용으로 조회한 결과입니다. 시트는 수정하지 않았습니다. 개인 기록 내용(비고 문구, 장소 등)은 이 문서에 옮기지 않고 구조만 기록합니다.

## 파일

- 제목: `히로_차계부` (소유자 계정의 내 드라이브)
- 스프레드시트 ID는 저장소에 커밋하지 않고, 앱 설정값으로 입력받는 방식을 검토합니다.
- 로캘 `ko_KR`, 시간대 `Asia/Tokyo` (UTC+9, 한국과 시차 없음)
- 탭: `시트1`(sheetId 0, 1001×29), `시트2`(sheetId 1966985373, 1000×26). 숨김 탭 없음

## `시트1` — 주유 기록

- 1행 헤더, 2행부터 기록. 조회 시점 기록 183행(2~184행), 기간 2024-01-12 ~ 2026-10-05, 날짜 오름차순
- 합계행·집계 탭 없음

| 열 | 헤더 | 내용 | 입력 방식 |
|---|---|---|---|
| A | 날짜 | 날짜 직렬값, 서식 `yyyy-mm-dd` | 직접 입력 |
| B | (없음) | 요일 | 수식 `=vlookup(weekday(An),$J$2:$K$8,2,0)` |
| C | 단가 | 원/리터. 일부 행 비어 있음. C2만 통화 서식 | 직접 입력 |
| D | 리터 | 정수 또는 소수(예: 금액 기준 주유 시 소수 3자리) | 직접 입력 |
| E | 주유비 | 원. 통화 서식 `[$₩-412]#,##0.00` | 대부분 수식 `=Cn*Dn`, 5개 행은 값 직접 입력 |
| F | 경과일수 | 직전 행과의 일수, 서식 `# 일` | 수식 `=days(An,An-1)` (2행은 비어 있음) |
| G | 누적 키로수 | 주행거리(km). 상당수 행 비어 있음 | 직접 입력 |
| H | (없음) | 비고(I열과 같은 의미). 2026년 이후 메모가 주로 이 열에 입력됨 | 직접 입력 |
| I | 비고 | 메모 | 직접 입력 |
| J:K | (없음) | 2~8행에 요일 조회표(1~7 → 일~토) | 고정값 |

확인된 특이 사항:

- **주유비 직접 입력 행:** 단가가 비었거나, 상품권 등으로 실제 결제액이 `단가×리터`와 다른 경우 E열에 값을 직접 넣었습니다. 주유비는 항상 `단가×리터`라고 가정할 수 없습니다.
- **빈 값:** 단가, 리터, 누적 키로수는 비어 있는 행이 있습니다. 0으로 바꾸지 않고 "값 없음"으로 다룹니다.
- **같은 날 여러 건:** 같은 날짜의 기록이 여러 행 있습니다(경과일수 0). 날짜는 고유 키가 될 수 없습니다.
- **메모 열 두 개:** H(헤더 없음)와 I(비고)에 메모가 나뉘어 있습니다. 사용자 확인 결과 둘 다 같은 "비고"입니다. 앱은 읽을 때 합쳐 보여주고 새 기록은 I열에만 씁니다.
- **새 행 추가 시:** B, E, F 수식이 행마다 상대 참조로 들어가 있으므로 앱이 새 행을 추가할 때 같은 수식을 함께 써야 기존 동작이 유지됩니다(쓰기 전략 합의 필요).

## `시트2` — 정비 기록

- 헤더 없음. 1행부터 기록. 조회 시점 정비 3건(7행)
- A: 날짜(직렬값, `yyyy-mm-dd`), B: 정비 항목, C: 업체/서비스, D: 정비 시점 누적 km(숫자)
- 사용자 확인 결과 D열은 금액이 아니라 누적 km입니다. 시트1의 같은 시기 누적 키로수와도 맞습니다. **현재 정비 금액 열은 없습니다.**
- 한 번의 정비에 항목이 여러 개면 첫 행에만 날짜·업체·km를 쓰고 다음 행에는 B열 항목만 씁니다.
- 업체나 km가 비어 있는 기록이 있습니다.
- 사용자 확인: 롯데렌터카 출장 서비스는 0원, 코스트코 타이어 교체는 비용이 있으며 나중에 기입 예정입니다.
- 수식 없음.

## 아직 확인하지 않은 것

- 조건부 서식, 데이터 확인(드롭다운), 보호 범위, 차트, 이름 지정 범위
- 시트1 L열 이후와 시트2 E열 이후의 값(조회 범위 밖)
