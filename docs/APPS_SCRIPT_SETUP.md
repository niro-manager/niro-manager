# Apps Script 설치·배포 안내

Niro Manager는 차계부 스프레드시트에 연결된 Apps Script 웹 앱으로 동작합니다. Google Cloud 프로젝트, OAuth 클라이언트, API 키는 필요 없습니다. 웹 앱은 소유자 계정으로 실행되고 소유자만 열 수 있어, 브라우저에 Google 계정으로 로그인되어 있으면 앱에서 따로 로그인하지 않습니다.

## 1. 올릴 파일 받기

다음 세 파일이 필요합니다: `index.html`, `Code.js`, `appsscript.json`.

- GitHub: 저장소 **Actions → CI → 최근 main 실행 → Artifacts → `apps-script`** 를 내려받아 압축을 풉니다.
- 또는 직접 빌드: Node.js 22 이상에서 `npm ci && npm run build` 후 `dist/` 폴더.

## 2. 테스트 복사본에 먼저 설치

1. Google Drive에서 테스트용 복사본을 엽니다. 2026-10-25 기준 복사본이 없으므로, 필요하면 원본 `히로_차계부_DB`에서 **파일 → 사본 만들기**로 이름에 "복사본"이 들어간 파일(예: `히로_차계부_DB (테스트 복사본)`)을 만듭니다.
2. **확장 프로그램 → Apps Script**를 엽니다.
3. 편집기의 `Code.gs` 내용을 모두 지우고 `Code.js` 내용을 붙여 넣습니다.
4. 파일 옆 **+ → HTML**로 이름이 `index`인 파일을 만들고, `index.html` 내용을 모두 붙여 넣습니다. 이름은 `index`여야 합니다.
5. **프로젝트 설정(톱니바퀴) → "편집기에서 appsscript.json 매니페스트 파일 표시"**를 켜고, 편집기의 `appsscript.json` 내용을 받은 `appsscript.json`으로 바꿉니다. Sheets 고급 서비스, 시간대(서울), 웹 앱 설정이 들어 있습니다.
6. 저장(Ctrl+S)합니다.

## 3. 웹 앱으로 배포

1. **배포 → 새 배포 → 유형 선택(톱니) → 웹 앱**.
2. 다음 사용자 인증 정보로 실행: **나**, 액세스 권한이 있는 사용자: **나만**.
3. **배포**를 누르고 권한을 승인합니다. "Google에서 확인하지 않은 앱" 화면이 나오면 **고급 → (프로젝트 이름)(으)로 이동**을 눌러 본인 스크립트를 허용합니다.
4. 나오는 **웹 앱 URL**(`https://script.google.com/macros/s/.../exec`)을 엽니다.
5. 기록 목록과 상단의 "테스트 복사본" 배지를 확인하고, 입력 화면에서 주유 한 건을 저장한 뒤 시트에서 확인합니다. 확인용 행은 확인 후 지웁니다.

## 4. 원본에 설치

원본 `히로_차계부_DB`에서 2~3단계를 똑같이 진행합니다(2026-10-25 이미 설치·배포됨). 상단 배지가 "원본 · 저장 가능"으로 보이면 원본에 연결된 것입니다. 휴대폰에는 아래 5절의 런처로 앱처럼 설치합니다.

## 5. 휴대폰에 앱으로 설치

Apps Script 주소(`script.google.com`)에는 앱 설치 정보(manifest)를 붙일 수 없어 Android Chrome에서 "이 앱을 설치할 수 없습니다"가 뜹니다. 그래서 GitHub Pages에 **설치용 입구 페이지(런처)** `https://niro-manager.github.io/niro-manager/`를 두었습니다. 런처는 이 기기에 저장한 웹 앱 주소로 바로 이동만 하며, 기록을 읽거나 저장하지 않습니다.

1. Apps Script 편집기에서 **배포 → 배포 관리**를 열고 웹 앱 URL(`https://script.google.com/macros/s/…/exec`)을 복사합니다. 끝이 `/dev`인 테스트 주소가 아니라 `/exec` 주소여야 합니다.
2. 휴대폰 브라우저로 런처 주소를 열고 웹 앱 URL을 붙여 넣은 뒤 **저장하고 열기**를 누릅니다. 주소는 이 기기의 브라우저에만 저장되고 저장소에는 올라가지 않습니다.
3. "주소를 저장했습니다" 화면에서 설치합니다.
   - Android Chrome: 메뉴(⋮) → **앱 설치**(또는 **홈 화면에 추가 → 설치**)
   - iPhone Safari: 공유 → **홈 화면에 추가**
4. 홈 화면(Android는 앱 서랍에도)의 **니로 차계부** 아이콘으로 엽니다. 런처가 웹 앱으로 바로 넘겨줍니다.

참고:

- 웹 앱은 다른 주소(`script.google.com`)라서 앱 화면 위에 얇은 주소 표시줄이 보일 수 있습니다(의도된 동작).
- iPhone은 홈 화면 앱이 Safari와 저장소를 따로 써서, 설치한 앱을 처음 열 때 주소를 한 번 더 붙여 넣어야 할 수 있습니다.
- 주소를 바꾸거나 지우려면 브라우저로 `https://niro-manager.github.io/niro-manager/?setup=1`을 엽니다. 웹 앱을 "새 배포"로 다시 만들어 URL이 바뀐 경우에만 필요합니다(업데이트 절차대로 새 버전을 올리면 URL은 그대로입니다).
- 인터넷이 끊겨 있으면 런처가 "오프라인입니다"를 보여주고, 연결되면 자동으로 웹 앱을 엽니다.
- 예전에 GitHub Pages 앱(PWA)을 설치했다면 같은 앱으로 인식되어 그 아이콘이 런처로 바뀝니다.

## 업데이트

새 버전을 받으면 `index`, `Code.gs`(및 바뀐 경우 `appsscript.json`)의 내용을 바꿔 붙여 넣고, **배포 → 배포 관리 → 연필(수정) → 버전: 새 버전 → 배포**를 누릅니다. 이렇게 하면 웹 앱 URL이 그대로 유지됩니다. "새 배포"를 만들면 URL이 바뀝니다.

명령줄을 쓰려면 [clasp](https://github.com/google/clasp)로 `dist/`를 올릴 수 있습니다(`rootDir: dist`). 이때 [Apps Script 사용자 설정](https://script.google.com/home/usersettings)에서 Apps Script API를 켜야 합니다. `.clasp.json`의 스크립트 ID는 저장소에 커밋하지 않습니다.

## 문제 해결

- **흰 화면이나 "권한 필요" 오류**: 브라우저에 여러 Google 계정이 로그인되어 있으면 Apps Script 웹 앱이 다른 계정으로 열려 실패할 수 있습니다. 시크릿 창에서 소유자 계정만 로그인하거나, 계정을 하나만 남기고 다시 엽니다.
- **"탭을 찾을 수 없습니다"**: 설정 화면의 주유·정비 탭 이름이 시트와 같은지 확인합니다.
- **"서버 함수 …이(가) 없습니다"**: `Code.gs`가 최신인지 확인하고 새 버전으로 다시 배포합니다.
- **"허용하지 않는 시트 변경 요청"**: 서버는 행 끼워 넣기·서식 복사·셀 값 쓰기만 허용합니다. 앱과 `Code.gs` 버전이 맞는지 확인합니다.

## 이전 방식 정리(선택)

Google Cloud 설정은 더 이상 쓰지 않습니다. 원하면 Google Cloud 콘솔에서 이 앱용 OAuth 클라이언트와 API 키를 삭제하고, GitHub Variables의 `VITE_GOOGLE_*` 값도 지워도 됩니다. GitHub Pages는 런처 배포에 다시 쓰므로 끄지 않습니다. 저장소 **Settings → Pages → Source**가 **GitHub Actions**인지 확인합니다.
